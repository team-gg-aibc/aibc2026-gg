# 사용자 평가 초안 (화면이 생긴 뒤, 11/18쯤부터)

> 원본 질문은 AIBC2026 Agent Ops 멘토링(2026-11-04)에서 받은 사용자 평가 질문(정량 12문항 · 정성 10문항)이다. 뜻은 그대로 두고 아래 낱말만 바꿨다. 문항 번호 · 순서 · 영역 이름도 원본 그대로다.
> 화면이 아직 없어서 화면 이름은 PRD 3판의 이름을 썼다: 담당자가 쓰는 **답변 화면**(문의 목록 · 3D 지도 · 답변 초안 카드, 4절 F3), 시민이 쓰는 **시민 문의 화면**(문의를 쓰고 답을 받는 한 화면, F6). 제품 이름이 정해지면(PRD 미정 17) 낱말 표만 고친다.
> 결과 칸은 실제로 받은 것만 채운다. 해 보기 전에는 「아직 해 보지 않음」이다. AI로 만든 가상 인물의 반응은 사용자 평가가 아니다.

## 0. 평가 전에 만든 사람이 먼저 할 것

화면이 생기면 만든 사람이 같은 12개 영역을 출시 전 점검표(PM이 가진 양식)로 먼저 돈다. 사용자에게 물었을 때 낮게 나올 곳을 미리 찾아 고치는 일이다. 특히 8번(오류 대응)은 PRD 6절의 「불러오지 못함」 · 「초안을 만드는 중」 상태가 실제로 보이는지, 9번(피드백)은 승인 뒤 시민 화면에 답이 도착하는지를 본다.

## 1. 바꾼 낱말

| 원본 | 담당자판 (답변 화면) | 시민판 (시민 문의 화면) |
|---|---|---|
| 시스템 | 답변 화면 | 시민 문의 화면 |
| 업무 (하는 일) | 문의에 답을 쓰는 일 | 문의하고 답을 받는 일 |
| 메뉴와 버튼 | 목록 · 카드 · 버튼 | 입력 칸과 버튼 |
| 기존 업무 방식이나 다른 시스템 | 지금(또는 전에) 답을 쓰시던 방식 | 기관 누리집이나 민원 창구에 글로 문의하던 방식 |

- 담당자판은 업무용 화면이라 영역 이름의 「업무」는 원본대로 둔다(Q5 「업무 효율성」).
- 핵심 행동(재는 것): 담당자판 = 답변 초안 카드를 열어 고치고 승인하기 / 시민판 = 문의를 보내고 답을 받기.

## 2. 안내 (응답자에게 보이는 첫 문장)

[답변 화면 / 시민 문의 화면]을 써 보신 경험을 묻습니다. 정답은 없고, 불편했던 점이 가장 도움이 됩니다. 이름이나 연락처는 묻지 않으며, 답은 이 화면을 고치고 경진대회 발표를 하는 데에만 씁니다. 5분쯤 걸립니다.

## 4. 쓰기 전 (숫자로 답, 담당자판에서 실제로 문의에 답을 써 본 사람에게만)

| 묻는 것 | 질문 |
|---|---|
| 쓰기 전 횟수 | B1. 답변 화면을 쓰기 전, 문의에 답을 쓰는 일을 일주일에 몇 번 하셨나요? (안 했으면 0) |
| 쓰기 전 시간 | B2. 그때 문의에 답을 쓰는 일 한 번에 보통 몇 분 걸렸나요? (B1이 0이면 비워 두세요) |

- 답은 `[자기 보고]`로 적는다. 이번 평가는 한 번 써 보는 평가라 「쓴 뒤 일주일 횟수」를 잴 수 없다. B1 · B2는 그 사람이 어떤 자리에서 왔는지를 보이는 맥락으로만 쓴다.
- 시민판에는 B1 · B2를 넣지 않는다. 시민의 문의는 한 해에 몇 번 하는 일이라 주 단위로 견줄 수 없다.

## 5. 정성 (서술형 · 인터뷰)

| 평가 영역 | 담당자판 | 시민판 |

| 첫인상 | Q1. 답변 화면을 처음 사용했을 때 어떤 느낌이 들었나요? | Q1. 시민 문의 화면을 처음 사용했을 때 어떤 느낌이 들었나요? |
| 긍정 경험 | Q2. 답변 화면을 사용하면서 가장 편리하거나 만족스러웠던 부분은 무엇인가요? | Q2. 시민 문의 화면을 사용하면서 가장 편리하거나 만족스러웠던 부분은 무엇인가요? |
| 불편 사항 | Q3. 사용하면서 가장 불편하거나 어려웠던 부분은 무엇인가요? | Q3. 사용하면서 가장 불편하거나 어려웠던 부분은 무엇인가요? |
| 사용 흐름 | Q4. 원하는 작업을 수행하면서 막히거나 헷갈렸던 순간이 있었나요? | Q4. 원하는 작업을 수행하면서 막히거나 헷갈렸던 순간이 있었나요? |
| 정보 구조 | Q5. 원하는 목록 · 카드 · 버튼이나 기능을 찾기 어려웠던 경험이 있다면 설명해 주세요. | Q5. 원하는 입력 칸과 버튼이나 기능을 찾기 어려웠던 경험이 있다면 설명해 주세요. |
| 기능 개선 | Q6. 개선이 가장 시급하다고 생각하는 기능은 무엇인가요? | Q6. 개선이 가장 시급하다고 생각하는 기능은 무엇인가요? |
| 추가 요구 | Q7. 현재 답변 화면에 없지만 추가되었으면 하는 기능은 무엇인가요? | Q7. 현재 시민 문의 화면에 없지만 추가되었으면 하는 기능은 무엇인가요? |
| 업무 활용 | Q8. 실제로 문의에 답을 쓰는 일을 할 때 답변 화면이 도움이 되는 부분과 그렇지 않은 부분은 무엇인가요? | Q8. 실제로 문의하고 답을 받는 일을 할 때 시민 문의 화면이 도움이 되는 부분과 그렇지 않은 부분은 무엇인가요? |

- 문의에 답을 써 본 적이 없는 참여자는 Q9를 6절 과제(조례 원문만 보고 답을 써 본 것)와 견줘 답하게 한다. 과제를 하지 않았다면 Q9는 건너뛰고 「건너뜀」으로 적는다.

끝맺음: 더 하고 싶은 말이 있으면 적어 주세요. (선택)

## 6. 과제 측정 (선택 — 할지는 PM이 정한다)

PRD 9절에 「담당자가 초안 한 건을 확인하고 승인하는 시간」은 「측정 전」이고 따로 잴지 정하지 않았다고 적혀 있다. 하기로 하면 담당자판 참여자에게 이렇게 잰다.

| 항목 | 정의 (재기 전에 고정, 결과를 본 뒤 바꾸지 않는다) |
|---|---|
| 문의 | PM이 고른 6종 문의 두 건(문의 갑 · 문의 을). 정답 근거 조항(조 · 항)을 PM이 조례 원문으로 미리 정해 둔다 |
| 직접 쓰기 | 조례 원문만 보고 시민에게 보낼 답과 근거 조항을 쓴다. 10분이 넘으면 멈추고 「10분 넘음」으로 적는다 |
| 카드로 쓰기 | 답변 초안 카드를 열어 고치고 승인한다. 카드는 모든 참여자에게 같은, 미리 저장한 엔진 답을 쓴다(엔진은 실행마다 답이 바뀔 수 있어서, PRD 3절 「재생 문의」와 같은 방식) |
| 순서 | 참여자 절반은 문의 갑을 직접 · 을을 카드로, 나머지 절반은 반대로(문의 난이도와 익숙해짐이 한쪽으로 쏠리지 않게) |
| 「한 번」 | 직접 쓰기: 답을 다 썼다고 말한 때 / 카드: 「승인」을 누른 때 |
| 시작 · 끝 | 문의를 처음 보여 준 때 → 위 「한 번」의 때. 초시계로 잰다 |
| 좋아진 방향 | 시간은 짧을수록, 맞는 근거 조항이 붙은 답은 많을수록 좋다 |
| 함께 적을 것 | 카드에서 고친 곳(결론 · 근거 · 말투 · 고치지 않음) |

- 꼬리표는 `[과제 측정]`이다. 참여자 대부분이 실제 담당자가 아니므로 「담당자의 시간」이라고 말하지 않고 「참여자 n명이 문의 2건으로 잰 시간」이라고 말한다.
- 이 과제의 숫자는 PRD 1절 한 문장의 숫자 칸(「근거가 붙은 답의 수」)과 다른 묶음이다. 섞어 쓰지 않는다.

## 7. 진행 순서 (한 사람에 30분쯤)

1. **동의 (2분)**: 무엇에 쓰는지(화면 고치기, 발표), 이름은 나가지 않는다는 것, 녹음하면 언제 지우는지를 말하고 허락을 받는다(`06-조심할-것.md`).
2. **할 일 한 문장 (1분)**: 설명하지 않는다. 담당자판: 「들어온 문의 가운데 [번호] · [번호] · [번호]에 답을 보내 주세요.」 세 건은 조항이 붙은 초안 카드 하나, 「6종 밖」 하나, 「조항을 찾지 못함」 하나로 고른다(PRD 3절 화면의 세 갈래를 다 만나게). 시민판: 「[주제]가 궁금하다고 생각하고 문의를 보내 보세요. 답이 오면 알려 주세요.」
3. **써 보기 (5~10분)**: 옆에서 보되 돕지 않는다. 막힌 곳과 그때 한 말을 적는다. 「그건 이렇게 쓰는 거예요」라고 하지 않는다.
4. **과제 측정 (선택, 10분)**: 6절.
5. **설문 (5분)**: 정량 12문항(담당자판은 B1 · B2 포함). 혼자 답하게 하고 만든 사람은 보지 않는다.
6. **인터뷰 (10~15분)**: 정성 Q1부터 순서대로. 설문에서 2점 이하를 준 영역은 그 자리에서 이어 묻는다(「Q8에 2점을 주셨는데, 그때 무엇을 하려고 하셨나요?」). 꼬리 질문은 「그때 무엇을 하려고 하셨나요?」, 「그다음엔 어떻게 하셨나요?」 두 가지면 된다.
7. **끝**: 「더 하고 싶은 말이 있나요?」. 그날 바로 9절 표에 한 말 그대로 적는다.

인터뷰가 어려운 사람에게는 정성 10문항을 서술형으로 설문 뒤에 붙인다(답은 선택).

## 8. 몇 명

| 무엇 | 사람 수 | 이유 |
|---|---|---|
| 정성 인터뷰 | 판마다 5명, 시간이 없으면 3명 | 다섯 명이면 큰 사용성 문제 대부분이 나온다(Nielsen Norman Group, 「Why You Only Need to Test with 5 Users」, 2000). 3명 중 2명이 같은 곳에서 막히면 고칠 곳으로 정한다 |
| 정량 설문 | 써 본 사람 전원. 평균을 발표하려면 12명 넘게 | 설문 평균은 12~14명쯤부터 안정된다는 비교 연구가 있다(Tullis & Stetson, 「A Comparison of Questionnaires for Assessing Website Usability」, 2004). 그보다 적으면 평균과 함께 분포(1~5점 각각 몇 명)를 꼭 보인다 |

- 담당자판에는 실제로 문의에 답을 써 본 사람을 한 명이라도 넣는다(현장 조사에서 만난 분께 화면을 보여 줄 수 있으면 가장 좋다). 나머지는 대리 참여자이고, 결과에 「실제 담당자 n명 · 대리 n명」을 나눠 적는다.
- 팀원은 참여자로 넣지 않는다. 친구 · 같은 학교 학생이 섞이면 몇 명인지 결과에 적는다.
- 10명보다 적으면 퍼센트 대신 「7명 중 5명」으로 말한다.

## 10. 발표에 넣는 꼴 (한 장)

| 칸 | 내용 |
|---|---|
| 제목 (주장 문장) | 「[n]명이 답변 화면을 써 보니 [실제로 잰 것]」 — 숫자는 실제로 잰 것만. 예시 꼴: 「대리 참여자 [n]명이 문의 2건을 풀어 보니, 카드로 쓴 답은 [n건 중 k건]에 맞는 근거가 붙었습니다」 |
| 큰 숫자 하나 | 과제 측정 Before → After(했다면), 꼬리표와 n |
| 12영역 평균 막대 | 낮은 둘 표시. n이 12보다 적으면 분포를 함께 |
| 인용 셋 | 좋았던 것 둘, 불편 하나(→ 고친 것과 날짜). 한 말 그대로, 「참여자 A」로 |
| 한 줄 | 설문 n · 인터뷰 n · 한 번 써 본 평가 · 실제 담당자 n명 · 대리 n명 · 질문 출처(멘토링 원본 질문) |
| 부록 | 문항 전체, 분포표, 과제 측정 정의 |

- 좋은 말만 고르지 않는다. 불편을 듣고 고친 이야기가 칭찬보다 믿음을 준다.
- 발표자료는 11/22 마감 뒤 고칠 수 없다. 11/20까지 모인 것만 넣는다.
