원본은 GitHub 이슈 · PR. 일은 이슈로 받고, 보고는 그 이슈의 댓글로 해요. 디스코드와 GG비서는 「봐 달라」는 신호만 보내요.

3
못 끝내면 PM 쪽이 이어받아요. 배분일 아침에 동규와 동규의 Claude 세션이 마저 돌려요. 벌이 아니라 주기를 지키는 장치예요.

끝 보고는 「의견: 채택 · 버림 · 보류」와 「어디에」(PR · 커밋), 결과 표(리더보드에 올린 두 줄)를 더해요. 「마감까지」는 끝남 · 못 끝냄으로 써요. 디스코드에는 이슈 링크만 올려요.
막히면 1시간 넘게 진전이 없으면 바로 「막힘」 보고. 무엇이 막혔는지 · 해 본 것 · 필요한 것을 써요.

점수는 이렇게 봐요

dev로만 재요.
dev = 개발용 문제(693문항). 마지막 확인용 holdout(174문항)은 팀원이 재지 않아요.
결과는 리더보드에. 켠 판 · 끈 판 두 줄을 남겨요.
리더보드 = 실험마다 켠 판 · 끈 판 점수를 한 줄씩 모은 표(docs/engine/leaderboard.md).
채택 기준: 가중 점수가 흔들림 폭의 두 배 넘게 오르고, 함정 정답률은 그대로 이상. 정하는 사람은 배분일의 동규예요.
흔들림 폭 = 아무것도 안 바꿔도 돌릴 때마다 생기는 차이. 세 번 돌려 70 · 72 · 71점이면 2점이라, 4점 넘게 올라야 채택해요.
가중 점수 = 문제 유형마다 점수를 따로 내서 킷 예시 비율(단순 3 · 조건 3 · 결합 3 · 함정 2)로 섞은 값.
