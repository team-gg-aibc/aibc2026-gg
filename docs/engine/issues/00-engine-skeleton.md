## 문제
- 영역: 엔진 (코드 · 데이터)
- 위치: 새 폴더 `engine/` (이름은 plan 6절 1번 결정을 따른다). 원본은 스타터 킷 커밋 8866d0e(동규 사본 `~/Projects/aibc2026-starter-kit/starter-kit`, 받은 그대로 + 검증을 solar-pro4 판정으로 바꾼 것)
- 왜: 팀 레포에 엔진 코드가 아직 없다. 킷은 검색 · 답 · 검증이 `rag.py` 한 파일에 다 있어서, 4명이 동시에 고치면 모든 PR이 같은 파일에서 부딪힌다. 단계마다 파일을 나눠 두면 사람마다 자기 파일만 고친다

## 재현
해당 없음 (옮기기 · 나누기)

## 작업 계약
- 선행 의존성: 없음

#### 할 일
- [ ] 킷 코드와 데이터를 옮긴다: 설정(`config.py`), 업스테이지 호출 한 곳(`upstage.py`), 조각 만들기(`build_index.py`), 별표 읽기(`parse_annex.py`), 서버(`app.py`), `data/`(ordinances.json · annex/*.md · chunks_*.json · vectors_*.npy). `.env`는 옮기지 않고 `.env.example`의 키 이름만 쓴다
- [ ] `rag.py`를 단계별 파일로 나눈다: 검색(`retrieve.py`) · 근거 고르기와 답 쓰기(`select.py`) · 확인 불가 판정(`verify.py`) · 출력 꼴(`contract.py`) · 흐름(`pipeline.py`: 질문 → 검색 → 고르기 → 판정 → 출력). 나누기만 하고 내용은 고치지 않는다
- [ ] 판단 기록 자리: `pipeline.answer(question)`이 응답과 함께 단계별 결과 · 걸린 시간 · 확인 불가를 낸 단계(사유 코드)를 돌려준다. 서버는 응답만 내보낸다
- [ ] 스위치 자리: `config.py`에 이슈별 절을 만들어 둔다(예: `# 03 조각 다듬기`). 각 이슈는 자기 절에만 줄을 더해 충돌을 줄인다
- [ ] `engine/README.md`: 설치 · 색인 만들기 · 서버 띄우기 명령, 데이터 출처(킷 10/1 판, `eval/source/`와 글자 차이 0 · 10-27 확인), 「조례는 다시 받지 않는다」

#### 하지 않을 것 (이 이슈의 경계)
- 검색 · 프롬프트 · 문턱 같은 동작 바꾸기 (각 가설 이슈 몫)
- 점수 재는 틀 (01), 출력 규격 강제 · 서버 방어 (02)
- 조례 다시 받기 (킷 데이터 그대로)
