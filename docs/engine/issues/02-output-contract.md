## 문제
- 영역: 엔진 (서버)
- 위치: `engine/contract.py`, `engine/server.py`, `engine/upstage.py`의 재시도 부분
- 왜: 채점은 마감 직후 한 번뿐이고, 아래 경우 그 문항은 0점이다: 90초 초과, 오류 응답(500 · JSON 깨짐), 필드 이름 틀림, 인용 없음, 자치구 인용, 함정에 지어낸 답. 서버가 꺼져 있으면 전 문항 0점이다. 킷은 75초가 지나면 「확인 불가」로 답하지만 뒤에서 호출이 계속 돌고, 429(호출 한도) 재시도가 마감 시간을 보지 않는다. 앞으로 여러 이슈가 인용을 만드는 새 길(후보 넓히기 · 묶음 · 통째로 읽기)을 더하므로 마지막 출구에서 한 번 더 막아야 한다

## 작업 계약
- 선행 의존성: 00 엔진 뼈대 병합 뒤

#### 할 일
- [ ] 마지막 출구 검사(`contract.py`): 네 칸(`answer` · `citation` · `source_url` · `effective_date`)과 꼴을 본다. 확인 불가는 언제나 킷의 꼴 그대로(`{"answer": "확인 불가", "citation": [], "source_url": "", "effective_date": ""}`). 「확인 불가」로 시작하는데 인용이 있거나, 인용이 비었는데 답 글이 있는 어중간한 답은 코드가 둘 중 하나로 맞춘다
- [ ] 인용 허용 목록: 색인에 있는 라벨(6종 조 · 항 · 별표)만 나간다. 겹침은 지우고, 개수 상한은 설정값(기본 4, 운영진 답이 오면 바꿈)
- [ ] `source_url` · `effective_date`는 코드가 원문 정보에서 채운다(모델이 쓰지 않음). 여러 조례를 인용하면 첫 인용의 조례 것을 쓴다
- [ ] 시간 예산: 서버가 문항마다 마감 시각(받은 때 + 75초)을 정해 흐름에 넘긴다. 재시도는 429 · 5xx · 시간 초과에만 하고(4xx는 다시 불러도 같다), 간격을 늘리며 마감을 넘기지 않는다. 마감이 지나면 기본은 킷처럼 확인 불가다. 「판정 전 답」을 내는 쪽이 나은지는 함정 점수와 정상 문항 점수가 맞바뀌는 선택이라 dev로 재서 PR에 적는다
- [ ] 동시 호출 제한: 업스테이지 호출 수를 설정값으로 묶는다(채점 때 여러 문항이 한꺼번에 와도 429로 무너지지 않게). 서버 프로세스(워커)를 여러 개 띄우면 판단 기록 파일 같은 로컬 파일을 같이 열어 충돌할 수 있으니 하나로 시작한다
- [ ] 어떤 오류에도 HTTP 200 + 규격 JSON. 요청 본문이 이상해도(질문 칸 없음 · 빈 문자열) 확인 불가로 답한다
- [ ] 판단 기록(00이 만든 자리)을 서버가 문항마다 한 줄 JSON으로 파일에 남긴다(키 · 개인 정보 없음)
- [ ] 스스로 시험(`python3 engine/contract.py --selftest`)을 만들고 CI에 넣는다: 일부러 깨진 답 → 고쳐짐, 목록 밖 라벨 → 빠짐, 가짜 지연 → 90초 안에 규격 답, 가짜 429 → 마감 안에서 포기

- 서버를 바깥에 띄우기 · 배포 (11 몫)
- 답 글 내용 고치기 (09 몫)
