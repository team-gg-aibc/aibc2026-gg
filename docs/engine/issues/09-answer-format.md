## 문제
- 영역: 엔진 (답 쓰기)
- 위치: `engine/select.py`(출력 틀 · 프롬프트), 새 파일 `engine/answer_check.py`(코드 검사)
- 왜: 답변 품질 20점은 심사위원이 본다. 강사는 「조건 판단은 첫 낱말을 네 · 아니요로」, 「결론 → 근거 → 요건 · 예외 → 출처」를 권했다(특강 1주차 1 · 5교시). 킷 실측에서 답 글에 근거 밖 안내가 섞였고(C3 「관할 구청에 문의하시면」), 강의 시연에서도 모델이 검색되지 않은 조항과 「14일」을 덧붙였다(2주차 5교시). 지금은 답에 근거가 없는 숫자 · 문장이 있어도 코드가 보지 않고, 판정이 답 전체를 버려 맞는 답까지 잃는다(킷 예시 M1)

## 재현
해당 없음 (실험)

## 작업 계약
- 선행 의존성: 04 후보 넓히기 병합 뒤(같은 파일 `select.py`)

#### 할 일
- [ ] 출력 틀(JSON 스키마)에 결론 칸(「네」 · 「아니요」 · 「정보」)과 「문장 목록 + 문장마다 근거 번호 + 그 근거에서 그대로 옮긴 구절(10자 이상)」을 넣는다. 인용은 살아남은 문장의 근거 번호로 코드가 만든다
- [ ] 구절 글자 대조(코드): 공백을 맞춘 뒤 구절이 그 근거 원문에 글자 그대로 있는지 본다. 없으면 한 번 다시 쓰게 하고, 또 없으면 그 문장을 지운다. 호출 없이 매번 같은 결과라 판정 호출보다 싸고 빠르다(LLMOps 과목 프로젝트가 쓴 관문)
- [ ] 코드 검사 (처음엔 기록만, dev에서 맞게 걸리는 것을 본 뒤 막기로)
  - 조건 판단 질문이면 첫 낱말이 「네」 · 「아니요」인가 (05 게이트의 유형 칸이 있으면 쓰고, 없으면 결론 칸)
  - 답의 숫자(「100분의 80」 = 80%, 「3,000～6,000」 = 3000~6000으로 맞춰서)가 인용한 근거에 있는가. 고르지 않은 후보에 있으면 그 근거를 인용에 더하고, 어디에도 없으면 한 번 다시 쓰게 하고, 그래도 없으면 그 문장을 지운다
  - 근거 번호가 없는 문장, 근거 밖 안내 문구(「문의 · 홈페이지 · 전화」)는 지운다
- [ ] 판정이 답 전체를 버리는 대신 걸린 문장만 지운다. 결론 문장이 지워지면 확인 불가로
- [ ] 스위치로 켜고 끈다

#### 하지 않을 것 (이 이슈의 경계)
- 계산을 코드가 하는 계산기 (2차 후보)
- 확인 불가 문턱 (10 몫)

#### 완료 조건
- [ ] dev 조건 판단 255문항에서 첫 낱말이 정답 열쇠(네 169 · 아니요 86)와 같은 비율, 숫자가 든 dev 274문항의 「근거에 없는 숫자」 비율, 과잉 포기율이 켠 판 · 끈 판으로 `experiments.md`에 있다
- [ ] 근거 정확도가 끈 판보다 떨어지지 않는다
- [ ] 단위 시험: 숫자 맞추기(「100분의 80」 = 80%, 「3,000～6,000」 = 「3000~6000」), 근거 번호 없는 문장 지우기
