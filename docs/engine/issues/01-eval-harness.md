## 작업 계약
- 선행 의존성: 00 엔진 뼈대 병합 뒤

#### 할 일
- [ ] `eval/run.py`: 묶음(`dev` · `holdout` · `stress` · `kit`)과 표본 수를 고르고, 엔진을 직접 부르거나(`--engine`) 서버 주소로 부른다(`--url`). 회색지대는 기본으로 뺀다
- [ ] 재는 것: 유형별 근거 정확도(킷 `score_citation`과 같은 규칙: 항까지 1 · 조까지 0.5), 킷 비율(단순 3 · 조건 3 · 결합 3 · 함정 2)로 섞은 가중 점수, 함정 정답률, 과잉 포기율, 형식 오류 수, 90초 초과 수, 지연 95% 지점(100문항 중 95번째로 느린 시간), 답 하나당 인용 수, 검색 적중률(판단 기록에 후보가 있으면)
- [ ] 틀린 문항마다 원인 태그를 판단 기록으로 붙인다: 정답이 후보에 없음 · 후보에 있는데 잘못 고름 · 판정이 맞는 답을 거절 · 함정에 답함 · 답이 있는데 확인 불가 · 시간 초과. 요약에 원인별 개수를 낸다(11/13 회의에서 2차 물결을 고르는 재료)
- [ ] 키가 없으면 검색 적중률만 잰다(임베딩 호출 없음). 지금 값 70.0%가 다시 나와야 한다
- [ ] 결과: 문항별 결과 파일(`eval/results/`, git에 올리지 않음)과 요약 한 줄(`experiments.md`에 붙일 표 줄)을 함께 낸다. `holdout`은 요약만 내고 문항별 결과는 남기지 않는다
- [ ] `docs/engine/experiments.md`: 기록 표 머리(plan 5-2절 칸)와 출발 점수 줄
- [ ] 출발 점수: 엔진을 바꾸지 않은 판(00 뼈대)을 dev 전체에 끝까지 돌린다. 같은 100문항 표본을 세 번 돌려 실행마다 흔들리는 폭(잡음)도 적는다

#### 하지 않을 것 (이 이슈의 경계)
- 엔진 동작 바꾸기
- 실험 추적 서비스(MLflow 등) 붙이기. 표 한 장으로 충분하다 (plan 5-2절)
- holdout으로 엔진 고치기

- [ ] `experiments.md`에 출발 점수 줄(유형별 · 가중 · 함정 · 과잉 포기 · 지연 · 비용), 잡음 폭, 틀린 원인별 개수가 있다
