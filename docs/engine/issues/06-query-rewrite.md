## 문제
- 영역: 엔진 (검색 전 단계)
- 위치: 새 파일 `engine/rewrite.py`(용어 사전 + 다시 쓰기), `engine/retrieve.py`(두 질문으로 찾아 합치기)
- 왜: 검색이 어려운 가장 큰 이유가 말투다. 평가셋을 만들 때 질문 413개(dev 기준)를 시민 말투로 바꿨는데(주차요금 → 주차비, 경형자동차 → 경차 · 모닝, 감면 → 깎아 줘요), 같은 문항을 키워드 검색으로 찾으면 바꾸기 전 질문은 98.6%, 바꾼 질문은 67.9%가 top-6 안에 든다(11/6 키 없이 잼). 바꾸기 전 질문은 조문 낱말을 따라 써서 실제보다 유리한 값이지만, 틈이 30점이다. 강사도 개선 목록 첫 줄에 「질문 재작성(쉬운 말 → 조문 용어)」을 들었다(킷 README · 특강 1주차 3교시)

## 작업 계약
- 선행 의존성: 01 점수 틀 병합 뒤. 03 조각 다듬기와 같은 사람이 하므로 03 다음에 한다(서로 기대지는 않음)

#### 할 일
- [ ] 용어 사전(코드, 호출 0): 시민 말 → 조례 용어. 출처는 조례 정의 조항과 **dev 문항만**이다. 항목마다 출처(정의 조항 또는 dev 문항 id)를 달고, 출처가 holdout 문항이면 코드가 막는다
- [ ] 사전으로 바꾼 질문을 키워드 검색에 더해(원래 질문 + 조례 용어) 키 없이 dev 적중률을 잰다
- [ ] Solar 다시 쓰기(호출 1번): 「조례에서 쓰는 한국어 말로 검색어를 다시 써라. 조건 · 숫자 · 장소는 그대로」. 원래 질문과 다시 쓴 질문으로 각각 찾아 점수를 합친다(한쪽이 망쳐도 다른 쪽이 남게). Solar가 한국어 질문을 영어 검색어로 바꾼 실측이 있어서(LLMOps 실습, solar-pro2) 다시 쓴 글에 한글이 없으면 버린다
- [ ] 다시 쓰기가 함정을 6종 용어로 끌어오지 않는지 dev 함정 42문항으로 본다
- [ ] 스위치 두 개(사전 · Solar 다시 쓰기)

#### 하지 않을 것 (이 이슈의 경계)
- 관할 판별 · 지시문 떼기 (05 몫)
- 조각 쪽에 가상 질문 붙이기 (2차 후보 「가상 질문 붙이기」)
- holdout 문항을 보고 사전 만들기

#### 완료 조건
- [ ] 사전만 켠 판의 dev 키워드 적중률(top-6)과, 다시 쓰기까지 켠 판의 혼합 적중률 · 끝까지 점수가 `experiments.md`에 있다
- [ ] 사전 항목 모두에 출처가 있고 holdout 출처는 0개다(코드로 검사)
- [ ] dev 함정 정답률이 끈 판보다 떨어지지 않는다
