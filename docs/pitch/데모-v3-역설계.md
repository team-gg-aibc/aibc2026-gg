# 데모 화면 첫 판 — 장면에서 거꾸로 정한 범위 (11/13 회의용 추천안)

> pitch-prep 점검 모드로 PRD 3판의 「심사위원이 나가며 할 한 문장」에서 거꾸로 데모 첫 판의 장면 · 범위를 정했다. 동규 확인 전 추천안이다. 발표 전략 원본(전략.md)은 PM 문서라 이 레포에 없다.

## 한 문장 (PRD 3판 1절, 동규 11-11 확정)

「그 팀은 시민 문의에 답을 쓰는 담당자에게 서울시 조례의 조항까지 붙은 답변 초안을 지도와 함께 건네고, 조례로 답할 수 없는 문의는 지어내지 않고 갈라 준 팀이었지.」

## 기억할 장면 하나 (와우 장면, 유형 ④ 사람이 하던 일을 몇 초에)

시민이 휴대폰 틀에서 공영주차장 선결제 환불을 묻는다 → 담당자 화면의 낮 지도에 그 주차장이 찍히고 목록에 「초안을 만드는 중」이 뜬다 → 몇 초 뒤 카드에 **답변 초안 · 근거 조항(조 · 항) · 그 조항의 원문 구절 · 시행일 · 원문 링크 · 소관 부서 / 처리 기관**이 함께 열린다 → 담당자가 한 줄을 고쳐 「승인」 → 시민 휴대폰에 답이 도착한다.

- 이 장면을 고른 까닭: 공영주차장 문의 답에 조 번호까지 적힌 것이 드물다는 문제 문장(PRD 1절 본 것 ②)에 곧바로 답한다. 실제 공개 글에서 기관은 조례 이름만 댔고 엔진은 두 번 다 같은 조 · 항(주차장 조례 제13조 제2 · 3항)을 댔다(PRD 8절 끝, 문의세트 보고 R02 · R05).
- 함께 보일 장면: 같은 목록에 들어온 6종 밖 문의(예: 불법 주정차 신고)가 초안 없이 「6종 밖」으로 갈라져 있는 것. 한 문장의 뒤 절(「지어내지 않고 갈라 준」)이다.

## 30초 대본 (초안)

| 구간 | 말 | 화면 |
|---|---|---|
| 상황 | 「주차 요금을 미리 냈는데 일찍 나왔다는 문의가 들어옵니다.」 | 시민 휴대폰 틀에서 보내기 |
| 긴장 | 「지금은 담당자가 조례를 찾아 답을 씁니다. 공개된 답에는 조 번호까지 적힌 것이 드뭅니다.」 | 지도에 주차장이 찍히고 「초안을 만드는 중」 |
| 장면 | 「엔진이 조례 원문에서 조항과 구절을 찾아 초안을 만들었습니다. 담당자는 고쳐서 승인만 합니다.」 | 카드: 근거 조항 · 원문 구절 · 소관 부서 → 고쳐 승인 |
| 의미 | 「시민은 근거 조항이 붙은 답을 받습니다. 조례로 답할 수 없는 문의는 지어내지 않고 따로 가릅니다.」 | 시민 휴대폰에 답 도착, 목록의 「6종 밖」 카드 |

## 데모 첫 판의 범위 (MoSCoW)

| 칸 | 무엇 | 꼬리표 |
|---|---|---|
| Must | 시민 문의 쓰기 → 담당자 목록 · 낮 지도 → 엔진이 그때 만든 초안 카드 → 고쳐 승인 → 시민 화면에 답 | 진짜 동작(엔진 실제 호출) |
| Must | 조항을 붙이지 못한 문의의 세 갈래 카드(6종 밖 / 조항을 찾지 못함 · 담당자 확인 / 불러오지 못함) | 진짜 동작(엔진 결과와 연결 실패로 가름) |
| Must | 재생 문의(미리 받아 둔 엔진 답) — 영상에서 문의마다 기다리지 않게 | 모의 처리 아님: 같은 통로로 미리 받은 실제 엔진 답. 카드에 「미리 받은 답」이라고 밝힌다 |
| Should | 부서별 보기(소관 부서 칩) | 진짜 동작(인용한 조례 → 소관 부서 표) |
| Should | 지도의 급지 · 공원 구분 | 자리 데이터는 손으로 붙인 표본(출처 표시) |
| Won't | 로그인 · 기관 시스템 연동 · 배포 주소 · 서버 재시작 뒤에도 남기 · 그 자리에서 쓴 문의의 장소 받기(미정 13) | 회의에서 「보강할 곳」으로 이야기 |
