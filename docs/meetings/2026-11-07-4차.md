## 1주기 실험이 무엇인가

「실험을 한다는 게 와닿지 않는다」는 질문이 나와 PM이 사람마다 다시 설명했다.

- 종희 #24: 스타터 킷은 모델이 고를 근거 조항 후보를 6개만 보여 준다. 10~20개로 늘리면 정확도가 얼마나 오르는지 본다. 넓혀서 더 잘 찾아온다면 앞 단계에 문제가 있거나, 처음부터 넓게 찾게 하는 편이 효율적이라는 뜻이다. 유의미하게 오르면 채택하고, 다음부터는 6개 대신 넓힌 수로 고정한다
- 동욱 #22: 점수는 맞는 답을 내는 것만큼 틀린 답(0점)을 줄여서도 오른다. 0점을 막는 장치를 넣고 다시 돌려 점수가 오르는지 내리는지 본다
- 건영 #23: 조례는 조 아래 항이 있고 그 밖의 덩어리도 같이 붙어 있다. 무엇을 넣고 빼고 어떻게 잘라야 점수가 오르는지 실험한다

## 실험을 하는 법

- 대회는 연구가 아니라 점수가 먼저다. 실험을 여러 개 돌려 점수가 높은 것을 찾고, 그걸 거꾸로 따라가며 공부한다. 과적합이 의심되면 가설을 더해 실험해 보고, 성능이 안 떨어지면 그게 정답 모델이다
- 대신 변인 통제는 한다. 시작할 때 상황을 다 이해하고 가설만 살짝 바꾼다. 에이전트가 주는 인사이트에는 한계가 있어서, 사람 머리에도 남아 있어야 서로 결합해 새것이 나온다
- 따로는 좋던 실험을 섞으면 떨어지는 일이 종종 있다. 그래서 실험 일지와 배운 점을 다 같이 남기고, 안 좋았던 실험도 버리지 않는다
- 1주기 실험이 끝나면 잘 된 것을 바탕으로 대회 제출 형태와 같은 채점 API를 만든다
- 지금 가설은 PM이 AI에게 세우게 한 것이다. Claude가 스타터 킷으로 출발 점수를 잰 뒤 점수를 올릴 가설을 세웠고, 말이 되는 것을 실험으로 넣었다. 「질문이 오면 어떤 조항으로 답하나」 같은 논리 쪽이 많아서, 임베딩 모델을 바꾸는 것 같은 엔지니어링 아이디어도 제안해 달라. PM 가설이 틀리거나 좁을 수 있다
- 다른 사람 실험과 점수는 #대시보드 그림과 각자 컴퓨터의 html(가설 나무)로 볼 수 있다. 안 해 본 가설이 보이면 언제든 「가설 제안」으로 올린다
- 여러 사람이 협업하는 가장 큰 이유는 컴퓨터가 여러 대라는 것이다. 실험을 나눠 돌리고, PM이 합쳐서 다시 나눈다

## AI 쓰는 환경

- 템포를 맞추려고 각자 AI와 어떻게 일하는지 나눴다. 코드는 터미널(Claude Code CLI), 그 밖의 일은 데스크톱 앱으로 나눠 쓰는 사람이 많았다. CLI는 코드 보기와 권한 주기가 편하다. PM은 Claude Code 데스크톱 앱에서 지휘 세션 하나로 여러 세션을 돌린다. 각자 생산성이 높은 것을 쓰면 된다
- 시작 지시는 #공지 글을 넣고 이슈 번호만 바꾸면 된다(맥락은 이슈에 다 있다). 컨텍스트가 80~90% 차면 인계 문서를 남겨 두면 문맥이 압축돼도 이어 갈 수 있다
