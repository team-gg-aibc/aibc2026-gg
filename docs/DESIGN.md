# DESIGN — 문의 답변 창구 시연 화면 (3판 첫 판)

> 모습 규칙만 둔다. 화면 문구는 `docs/content/`(A-01_답변화면 · C-01_답변초안카드 · U-02_시민문의)에만 있다. 이 파일은 Claude Design 시안에서 고른 것이 아니라 `demo/desk/web/style.css`를 보고 거꾸로 뽑은 것이다(11-11). 동규가 Claude Design으로 새 시안을 고르면 이 파일을 그 결과로 바꾼다.

## 1. 배치

- 큰 화면(가로 1200px 이상): 낮 3D 지도를 화면 전체에 깔고, 그 위에 세 칸을 띄운다. 왼쪽부터 시민 휴대폰 틀(330px) → 담당자 문의 목록(400px) → 답변 초안 카드(오른쪽, 400~500px). 가운데 빈 곳은 지도이고, 카드를 열면 그 문의의 자리가 이 빈 곳에 오도록 지도가 옮겨 간다. 처음 모습도 칸에 가리지 않는 곳을 가운데로 잡는다(칸의 실제 끝을 재서 지도 여백으로 준다).
- 좁은 화면(1200px 미만, 휴대폰 포함. 1100~1199px에서는 카드가 목록을 덮어서 기준을 1200px로 둔다): 위에 탭 두 개(시민 화면 · 담당자 화면)를 두고 하나씩 보인다. 담당자 화면은 지도 띠(높이 240px) → 목록 → 카드 순으로 세로로 쌓는다. 목록에서 문의를 누르면 카드 자리로 화면이 내려간다. 같은 정보 · 같은 순서로 폭만 바뀐다(반응형).
- 카드 안 순서는 content가 정한 정보 위계 그대로: 문의 → 답변 초안 → 근거 → 소관 부서와 처리 기관 → 처리 상태 → 엔진 답의 출처. 승인은 근거를 다 본 뒤에 오는 자리다.
- 조항을 붙이지 못한 갈래(6종 밖 · 조항을 찾지 못함 · 불러오지 못함)는 답변 초안 칸 대신 안내 한 덩어리만 보인다(초안을 지어 보이지 않는다).

## 3. 글자

- 제목 · 본문 모두 Pretendard(가변 글꼴, 웹폰트). 도현체를 쓰지 않은 까닭: 공공기관 화면이라 믿음이 앞서고, 도현체에는 화면에 자주 나오는 가운뎃점(·)이 없다.
- 크기: 화면 제목 21~22px · 구역 제목 16~17px · 본문 15px · 작은 안내 13px · 배지 12.5px. 이 다섯 단계 밖의 크기를 새로 만들지 않는다.
- 한글은 낱말 단위로 줄을 바꾼다(`word-break: keep-all`).

## 4. 부품

| 부품 | 모습 | 쓰는 곳 |
|---|---|---|
| 배지(Badge) | 알약, 앞에 점, 테두리 없음, 읽기만 | 문의 상태 · 출처 · 확인 필요 |
| 칩(Chip) | 알약, 테두리 있음, `aria-pressed`, 고르면 먹색 채움 | 소관 부서로 거르기 |
| 보기(Segmented) | 붙은 버튼 묶음, 고른 것 먹색 | 전체 · 승인 전 · 승인 완료 |
| 줄(Row) | 흰 카드, 왼쪽 번호 동그라미, 둘째 줄에 상태 배지, 셋째 줄에 출처 · 소관 부서 | 들어온 문의 목록 |
| 지도 점(Pin) | 흰 테두리 알약, 왼쪽 번호, 오른쪽 자리 이름, 바탕은 상태 묶음 색 | 지도 |
| 상태 고르기(Radio) | 선택지를 모두 세운 라디오 묶음. 막힌 선택지는 점선 테두리 · 흐린 글자 + 바로 아래 까닭 | 처리 상태(검토 중 · 승인 완료) |
| 확인 창(Alert Dialog) | 가운데 창, 뒤를 어둡게. 버튼은 그만두기(테두리) 먼저, 보내기(채움) 나중 | 승인, 처음 상태로 되돌리기 |
| 불러오는 중(Skeleton) | 회색 막대 세 줄이 흐름, `aria-busy`, 움직임 줄이기 설정이면 멈춤 | 초안 작성 중 카드 |
| 휴대폰 틀 | 검은 테두리 40px 둥근 모서리, 안은 흰 화면, 이름표와 값은 위아래로 | 시민 화면 |

## 5. 지킬 것

- 색만으로 구별하지 않는다. 모든 상태는 배지 글자(content의 `상태 | 보일 말` 표)와 함께 보인다.
- 누르는 것은 44px 이상(칩은 36px, 목록 칩이라 예외로 둠 — 휴대폰 손가락 점검 때 다시 볼 것).
- 한 화면에 채운 버튼은 하나(시민 화면: 문의 보내기 · 확인 창: 보내기).
- 상태를 바꾸는 곳은 고를 수 있는 상태를 모두 보이고, 되돌릴 수 없는 변경은 고른 뒤 확인 창으로 받는다. 승인한 뒤 「검토 중」은 지우지 않고 막고 까닭을 보인다(oss-hub 원칙).
- 「들어온 문의 없음」과 「불러오지 못함」은 다른 문장 · 다른 모습이다.
- 오류는 그 자리 아래에 글로 남기고(`role="alert"`), 성공은 조용히 알린다(`role="status"`). 코드 오류 글(영어)을 화면에 보이지 않는다.
- 기관 로고 · 공식 시스템 이름 · 실존 브랜드를 쓰지 않는다. 지도 출처 표시는 지우지 않는다.
