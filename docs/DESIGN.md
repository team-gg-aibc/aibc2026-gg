# DESIGN — 문의 답변 창구 시연 화면 (3판 첫 판)

> 모습 규칙만 둔다. 화면 문구는 `docs/content/`(A-01_답변화면 · C-01_답변초안카드 · U-02_시민문의)에만 있다. 이 파일은 Claude Design 시안에서 고른 것이 아니라 `demo/desk/web/style.css`를 보고 거꾸로 뽑은 것이다(11-11). 동규가 Claude Design으로 새 시안을 고르면 이 파일을 그 결과로 바꾼다.

## 1. 배치 (2판 · 11-11 저녁 「한 칸 작업대 + 오른쪽 넓은 지도」, B안)

- 고른 까닭: 레퍼런스 15곳(관제 · 상담 · 공공 디자인 시스템 · 지도 · 접기 규칙)에서 배치 안 셋을 견줘 골랐다(`_orch-tools/reports/demo-v3/2판/레퍼런스-배치.md`). 지도가 가장 넓고, 담당자가 가장 많이 하는 「문의 고르기 → 초안 읽고 고치기 → 승인」이 한 칸 안에서 끝나며, 시연이 왼쪽부터 시민 → 담당자 → 장소로 흐른다.
- 큰 화면(가로 1200px 이상): 맨 위 띠(높이 60px: 화면 이름 · 초안 자동 작성 상태 · 칸 버튼 셋) 아래에 서울 3D 지도를 화면 전체에 깔고, 왼쪽부터 시민 휴대폰 틀 → 작업 칸(폭 400~470px) 둘을 띄운다. 작업 칸에는 문의 목록과 답변 초안이 번갈아 들어온다(초안을 열면 목록 자리에, 「문의 목록으로」를 누르면 다시 목록). 나머지 오른쪽이 모두 지도이고, 지도 여백은 「보이는 왼쪽 칸 가운데 가장 오른쪽 끝」을 재서 준다. 카드를 열면 그 문의의 장소가 보이는 지도의 가운데로 날아간다.
- 잰 값(초안을 연 뒤 지도가 보이는 폭): 1440px 창 586px · 1280px 창 499px(1판은 162px · 22px). 시민 화면을 접으면 954px · 842px.
- 칸 접고 펴기: 맨 위 띠 오른쪽, 늘 같은 자리의 글자 버튼 셋(시민 화면 · 문의 목록 · 답변 초안). 펴져 있는 칸은 흰 바탕 테두리 버튼(「… 접기」), 접혀 있는 칸은 먹색으로 채운 버튼(「… 펴기 · 보기」)이라 다시 펼 곳이 눈에 띈다. 아이콘만 쓰지 않는다. 「답변 초안」 버튼은 문의를 고르기 전에는 막혀 있다.
- 휴대폰 틀: 요즘 휴대폰 화면 비율(393×852 CSS px ≈ 9:19.5)을 지킨다. 높이는 창 높이에 맞추고(많아야 740px) 너비는 비율로 정하며, 내용은 화면 안에서 스크롤한다. 위쪽 가운데에 카메라 자리 하나. 답이 도착하면 휴대폰 화면이 「받은 답」으로 내려간다.
- 지도는 서울시만: 처음 모습은 서울 전체가 보이는 지도 가운데에 오게 맞추고, 움직일 수 있는 범위는 서울 둘레(경계 상자 ± 경도 0.7° · 위도 0.35°)로 묶는다. 서울 밖은 옅은 회색(`#e9ecf0`, 불투명 0.93)으로 가리고 서울 경계에 남색 선(2.5px)을 긋는다. 경계 자료: OpenStreetMap 「서울특별시」 행정 경계(relation 2297418, ODbL, Overpass API 2026-11-11 받음, 0.0004° 단순화) → `demo/desk/web/data/seoul.geojson`.
- 지도가 맡는 일: 「같은 문의도 어느 주차장 · 어느 공원이냐에 따라 답하는 규정이 달라진다」를 보이는 것(동규 11-11). 통계 층은 두지 않는다.
- 가상 문의 데이터 출처: 화면 오른쪽 아래, 지도 저작권 표시 바로 위에 작은 회색 글씨(11.5px, `#5f6b7a`, 옅은 흰 바탕으로 지도 위 어디서나 4.5:1 넘게). 좁은 화면에서는 맨 아래.
- 좁은 화면(1200px 미만, 휴대폰 포함): 맨 위 띠는 이름 · 상태만 두고 칸 버튼 대신 탭 두 개(시민 화면 · 담당자 화면). 담당자 화면은 지도 띠(높이 240px) → 작업 칸 순으로 쌓고, 초안을 열면 목록 자리에 카드가 들어온다. 휴대폰 틀은 화면 폭에 맞춘 같은 비율.
- 카드 안 순서는 content가 정한 정보 위계 그대로: 카드 머리(문의 목록으로 · 이전 문의 · 몇 번째 / 모두 · 다음 문의) → 문의 → 답변 초안 → 근거 → 소관 부서와 처리 기관 → 처리 상태 → 출처 줄. 승인은 근거를 다 본 뒤에 오는 자리다.
- 조항을 붙이지 못한 갈래(6종 밖 · 조항을 찾지 못함 · 불러오지 못함)는 답변 초안 칸 대신 안내 한 덩어리만 보인다(초안을 지어 보이지 않는다).

## 3. 글자

- 제목 · 본문 모두 Pretendard(가변 글꼴, 웹폰트). 도현체를 쓰지 않은 까닭: 공공기관 화면이라 믿음이 앞서고, 도현체에는 화면에 자주 나오는 가운뎃점(·)이 없다.
- 크기: 화면 제목 21~22px · 구역 제목 16~17px · 본문 15px · 작은 안내 13px · 배지 12.5px. 이 다섯 단계 밖의 크기를 새로 만들지 않는다.
- 한글은 낱말 단위로 줄을 바꾼다(`word-break: keep-all`).

## 4. 부품

| 부품 | 모습 | 쓰는 곳 |
|---|---|---|
| 배지(Badge) | 알약, 앞에 점, 테두리 없음, 읽기만 | 문의 상태 · 출처 · 확인 필요 |
| 칩(Chip) | 알약, 테두리 있음, `aria-pressed`, 고르면 먹색 채움 | 소관 부서로 거르기 |
| 보기(Segmented) | 붙은 버튼 묶음, 고른 것 먹색 | 전체 · 승인 전 · 승인 완료 |
| 줄(Row) | 흰 카드, 왼쪽 번호 동그라미, 둘째 줄에 상태 배지, 셋째 줄에 출처 · 소관 부서 | 들어온 문의 목록 |
| 지도 점(Pin) | 흰 테두리 알약, 왼쪽 번호, 오른쪽 자리 이름, 바탕은 상태 묶음 색 | 지도 |
| 상태 고르기(Radio) | 선택지를 모두 세운 라디오 묶음. 막힌 선택지는 점선 테두리 · 흐린 글자 + 바로 아래 까닭 | 처리 상태(검토 중 · 승인 완료) |
| 확인 창(Alert Dialog) | 가운데 창, 뒤를 어둡게. 버튼은 그만두기(테두리) 먼저, 보내기(채움) 나중 | 승인, 처음 상태로 되돌리기 |
| 불러오는 중(Skeleton) | 회색 막대 세 줄이 흐름, `aria-busy`, 움직임 줄이기 설정이면 멈춤 | 초안 작성 중 카드 |
| 휴대폰 틀 | 검은 테두리 40px 둥근 모서리, 안은 흰 화면, 이름표와 값은 위아래로 | 시민 화면 |

## 5. 지킬 것

- 색만으로 구별하지 않는다. 모든 상태는 배지 글자(content의 `상태 | 보일 말` 표)와 함께 보인다.
- 누르는 것은 44px 이상(칩은 36px, 목록 칩이라 예외로 둠 — 휴대폰 손가락 점검 때 다시 볼 것).
- 한 화면에 채운 버튼은 하나(시민 화면: 문의 보내기 · 확인 창: 보내기).
- 상태를 바꾸는 곳은 고를 수 있는 상태를 모두 보이고, 되돌릴 수 없는 변경은 고른 뒤 확인 창으로 받는다. 승인한 뒤 「검토 중」은 지우지 않고 막고 까닭을 보인다(oss-hub 원칙).
- 「들어온 문의 없음」과 「불러오지 못함」은 다른 문장 · 다른 모습이다.
- 오류는 그 자리 아래에 글로 남기고(`role="alert"`), 성공은 조용히 알린다(`role="status"`). 코드 오류 글(영어)을 화면에 보이지 않는다.
- 기관 로고 · 공식 시스템 이름 · 실존 브랜드를 쓰지 않는다. 지도 출처 표시는 지우지 않는다.
