# 평가셋 (AI 초안)

우리 엔진이 몇 점인지 미리 재고, 「확인 불가」 기준값을 맞추려고 만든 문제집이다. 기준값이 너무 낮으면 함정 문항이 0점이 되고, 너무 높으면 멀쩡한 문항이 0점이 된다. 실제 채점은 마감 직후 비공개 문항으로 한 번뿐이라 우리 문제집이 있어야 한다. 10/27 2차 회의 안건 3의 결정대로 **AI가 먼저 만들고 사람이 조례별로 검수**한다. 이 폴더는 그 AI 초안이고, 아직 아무도 검수하지 않았다(`checked_by`가 모두 비어 있다).

## 문항 형식

스타터 킷 `sample_questions.json`과 같은 꼴이다. 안건 3에서 정한 `made_by` · `checked_by` 두 칸을 더했다(킷 채점기는 모르는 칸을 무시한다). 키 8개를 이 순서대로 쓴다.

```json
{
  "id": "parking-S001",
  "type": "단순 조회",
  "question": "서울시 공영주차장 1급지 노상주차장 요금은 5분에 얼마인가요?",
  "gold": [["서울특별시 주차장 설치 및 관리 조례 별표 1", "서울특별시 주차장 설치 및 관리 조례 제6조 제1항"]],
  "answer_key": "500원 (별표 1, 「1급지」 「노상주차장」 1회 주차 시 5분당)",
  "note": "",
  "made_by": "ai",
  "checked_by": ""
}
```

- `type`: `단순 조회` · `조건 판단` · `여러 조항 결합` · `근거 없음 (함정)` (킷과 같은 이름)
- `id`: `<키>-S###` 단순 조회, `-C###` 조건 판단, `-M###` 여러 조항 결합, `-G###` 회색지대, `-T###` 함정
- `gold`: 바깥 목록 = 꼭 있어야 하는 근거들, 안쪽 목록 = 「이 중 하나면 정답」. 함정은 `[]`. 조항은 항까지 쓰고, 항이 없는 조는 조까지 쓴다. 별표 문항은 별표와 그 별표를 부르는 조항을 대안으로 함께 둔다.
- `answer_key`: 채점하는 사람이 볼 정답 열쇠다. 「」로 감싼 말은 원문 글자 그대로라서 자동 점검이 gold 원문에서 찾아본다. 조건 판단은 「네」 또는 「아니요」로 시작한다.
- `note`에 쓰는 표시
  - `[사람 확인] 이유`: 문항을 쓴 쪽(AI 또는 사람)이 확신하지 못한 것
  - `[사람 확인: 자동 점검] …`: `check.py --write`가 단 표시. 다시 돌리면 지우고 새로 쓰니 그 뒤에 글을 덧붙이지 않는다
  - `[회색지대] …`: 정답을 아직 정하지 않은 위임 규정형(아래 절)
  - `주의: …`: 함정에서 엔진이 끌려가기 쉬운 비슷한 조항
  - `점검 핵심어: a, b`: 함정에만 쓴다. 6종 원문에 이 말이 있으면 자동 점검이 알린다

## 만든 방법

1. **원문 받기**: `fetch_source.py`가 법제처 국가법령정보 OPEN API에서 6종을 받아 조 · 항(①②…) · 호(1. 1의2. 2. …) · 별표로 나눈다. 나눈 조각을 다시 이어 붙이면 받은 원문과 글자 하나까지 같은지 확인했다(6종 527단위). 응답 안의 상세 링크에 인증키가 그대로 들어 있어서 저장하기 전에 지운다.
2. **문항 만들기**: Claude(Opus 5.5)가 조례 하나씩 맡은 작업 6개로 나눠 동시에 썼다. 업스테이지 API는 쓰지 않았다. 규칙은 이렇다.
   - 항마다(항이 없는 조는 조마다, 별표는 별표마다) 그 단위 안에 답이 있는 질문을 거꾸로 만든다. 정답 조항(`gold`)은 만들 때 정한 그 단위다.
   - 항 하나짜리 문항은 단순 조회나 조건 판단으로 쓴다. 조건 판단에는 일부러 조건에 안 맞는 경우를 물어 「아니요」 문항을 섞었다(조건 판단 318개 중 113개).
   - 여러 조항 결합은 원칙 + 예외 · 감면 · 절차를 다른 항에서 묶었다. 예: 주차장 제7조 제1항 감면율 + 제3항 「감면 사유가 둘 이상이면 높은 하나만」.
   - 함정은 `common`에 모았다. 주제는 6종과 비슷한데 규정은 다른 데 있는 것들이다(상위 법률 · 자치구 조례 · 다른 시 · 도 조례 · 6종 밖 서울시 조례 · 운영 공고). note에 「실제 규정」으로 적은 법률 조항과 조례 이름은 법제처 API로 조문을 직접 찾아 확인했다. 찾지 못한 것은 「확인 필요」라고 적었다.
   - 시민 말투로 쓰되 조문을 그대로 베끼지 않게 했다. 그래도 AI가 조문을 보고 쓴 질문이라 실제 질문보다 쉽다(아래 「점수 잴 때」의 키워드 검색 결과). 검수에서 말투를 고치는 이유다.
3. **자동 점검**: `check.py`가 아래를 본다. 걸린 문항은 note에 `[사람 확인: 자동 점검]`을 남긴다.
   - 형식(키 8개 · 유형 이름 · id 중복), gold 라벨이 원문에 실제로 있는 조 · 항 · 별표인지(자치구 조례 라벨은 여기서 막힌다)
   - 함정이 아닌 문항: answer_key의 숫자와 「」로 감싼 핵심어가 gold 원문에 있는지
   - 함정: note의 `점검 핵심어`가 6종 원문 어디에도 없는지
   - 질문이 조문을 20자 넘게 그대로 옮겼는지, 조건 판단이 「네 / 아니요」로 시작하는지

## 검수 방법

1. 맡은 파일(`questions_<키>.json`)과 원문 사본(`source/<키>.md`)을 나란히 연다. 원문 사본에서 막히면 위 표의 법제처 링크로 확인한다.
2. 문항마다 아래를 본다.
   - **정답 조항 대조**: `gold`의 조 · 항에 정말 답이 있는지, 더 맞는 항이 따로 있지는 않은지 본다. 단순 조회 · 조건 판단은 표본(5개 중 1개 이상)으로 보고, **전부 볼 것은 빠짐없이** 본다.
   - **시민 말투로 고치기**: 조문 낱말을 그대로 쓴 질문은 실제로 들을 법한 말로 바꾼다. 예: 「주차요금 감면 대상인가요?」 → 「장애인 차는 주차비 깎아 줘요?」. 정답 조항이 달라지지 않게 고친다.
   - **answer_key**: 원문에 없는 사실이 들어가지 않았는지, 조건 판단의 「네 / 아니요」가 맞는지 본다.
   - 다 본 문항은 `checked_by`에 담당 이름을 쓴다. 해결하지 못한 문제는 note에 `[사람 확인] 이유`로 남기고 PR 「정리」에 적는다.
3. **함정**(D): 6종 어디에도 정말 없는지 본다. `source/*.md` 6개에서 질문의 핵심어를 검색해 보고, 놓친 말이 있으면 `점검 핵심어`에 더한다. 잘못된 함정은 「확인 불가」 기준값을 망치니, 의심스러우면 빼거나 일반 문항으로 바꾼다.
4. **자기 말로 묻는 질문 더하기**: 주변에서 실제로 들은 질문이면 더 좋다. `made_by`에 이름을 쓰고, id는 그 파일의 같은 유형 다음 번호로 잇는다.
5. 고친 뒤 `python3 eval/check.py`를 돌려 `✗`(형식 오류)가 없게 한다. `python3 eval/check.py --write`는 자동 점검 표시를 note에 새로 쓴다. 고친 결과는 PR로 올린다.

## 원문에서 이상해 보인 곳

문항을 쓰다 찾은 것이다. 엔진이 틀리기 쉬운 곳이라 검수할 때 같이 본다.

- **항 번호가 밀린 흔적**: 도시공원 제23조 제5항 「제3항에 따른 과태료」(→ 제4항), 도시공원 제20조 제4항 끝의 「2019년 12월 31일까지 유효」 꼬리표, 금연 제5조 제5항 「제1항제4호부터 제9호」(제4호 · 제8호는 2026.1.5 삭제)
- **인용 번호 어긋남**: 동물보호 제6조 제1항 「제2조제2호」(정의는 제7호), 주차장 별표 3 제목 「(제21제2항 관련)」(「조」 빠짐)
- **오기로 보이는 글자**: 주차장 제18조 제2항 제2호 「1할 계산」, 도시공원 제26조 제2항 「부원장」
- **조 번호가 옮겨 간 조례**: 동물보호는 2025-09-29 개정으로 뒤쪽 조가 2칸 밀렸다(수수료 감면이 옛 제26조 → 제28조, 놀이터 제27조 → 제29조 등). 청년은 2020-03-26에 제19조~제22조가 한 칸씩 밀렸고(→ 제20조~제23조), 2025-01-03에 표창이 제24조에서 제25조로 옮겨 갔다. 옛 판 자료로 답하면 조 번호가 틀린다.

## 점수 잴 때

- 회색지대는 운영진 답이 오기 전까지 빼고 잰다. 답이 오면 그 기준으로 `gold` · `answer_key`를 정하고 `[회색지대]` 표시를 지운다.
- 유형마다 따로 잰 뒤 킷 비율(단순 3 · 조건 3 · 결합 3 · 함정 2)로 가중 평균한다.
- 킷 채점기로 돌리는 법(파일 여러 개를 하나로 합치고 회색지대를 뺀다):

```bash
python3 -c "import json,glob; json.dump([q for f in sorted(glob.glob('eval/questions_*.json')) for q in json.load(open(f)) if '[회색지대]' not in q['note']], open('/tmp/eval_all.json','w'), ensure_ascii=False)"
```

```bash
cd <스타터 킷 폴더> && python -X utf8 check.py --retrieval --questions /tmp/eval_all.json
```

- **AI 초안은 실제보다 쉽다.** 킷의 키워드 검색만으로(API 키 없이) 돌리면 정답 근거가 상위 6개 안에 드는 비율이 단순 조회 98% · 조건 판단 92% · 여러 조항 결합 77%다(757문항, 2026-10-27). 같은 방식으로 킷 예시 문항은 69%다. 질문이 조문 낱말을 따라 써서 그렇다. 검수에서 시민 말투로 고친 뒤 다시 재면 이 숫자가 내려가야 정상이다.
- 「확인 불가」 기준값은 함정(`common`)과 「어렵지만 답이 있는」 문항(결합형 · 별표 문항)을 둘 다 맞히는 지점에서 고른다.
