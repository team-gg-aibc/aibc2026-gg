# 문의 답변 창구 시연 화면 (PRD 3판 첫 판)

시민이 문의를 쓰면 담당자 화면(낮 3D 지도와 문의 목록)에 들어오고, 엔진이 서울시 조례 6종의 근거 조항이 붙은 **답변 초안**을 만들고, 담당자가 고쳐 승인하면 시민 화면에 답이 가는 한 바퀴가 실제로 돈다. 조항을 붙이지 못한 문의는 초안 없이 셋(6종 밖 · 조항을 찾지 못함 · 불러오지 못함)으로 갈라 보인다.

**가상 표시**: 시연 문의 가운데 V로 시작하는 것은 가상 문의(NVIDIA Nemotron-Personas-Korea, CC BY 4.0을 바탕으로 만든 것)이고, R로 시작하는 것은 공개 게시판 글의 요지다(이름 · 전화 · 차량번호 없음). G01은 「6종 밖」 카드를 보이려고 팀이 직접 쓴 가상 문의다(자치구 조례를 이름으로 듦, 화면에 「가상 문의(팀이 쓴 글)」). 지도 점의 자리는 시연용으로 손으로 놓은 대략 위치다. 담당자 화면은 여러 담당자에게 간 문의를 한 화면에 모아 보인 것이다. 화면에도 같은 내용이 늘 보인다.

## 띄우는 법 (레포 맨 위에서)

엔진까지 실제로 부르기 — 한 줄(엔진은 `engine/README.md` 「설치」의 가상 환경 파이썬, `.env`에 업스테이지 열쇠가 있어야 한다):

```bash
OPENBLAS_NUM_THREADS=1 ENGINE_CONFIG=eval/configs/pm-flow2-v7.json .venv/bin/python demo/desk/engine_trace.py & python3 demo/desk/server.py
```

엔진 없이 미리 받은 답으로만 — 한 줄:

```bash
DESK_ENGINE=saved python3 demo/desk/server.py
```

그다음 브라우저에서 http://127.0.0.1:8770 을 연다. 지도 · 글꼴은 인터넷(CDN)에서 받는다. 끝낼 때는 Ctrl+C(엔진을 `&`로 띄웠으면 `kill %1`).

## 무엇이 실제 호출이고 무엇이 미리 받은 답인가

| 무엇 | 어떻게 도나 | 화면 표시 |
|---|---|---|
| 시민 화면에서 보낸 문의 | 화면 서버가 그때 엔진을 HTTP로 부른다(새 흐름 7판, 5~8초) | 카드 아래 「엔진에서 지금 받은 답」 + 받은 시각 · 걸린 초 |
| 「시연 문의 들여오기」로 들어오는 10건 | 같은 통로(`server.py --save`)로 엔진에 미리 넣어 받아 둔 답(`data/saved.json`). 영상에서 문의마다 기다리지 않으려는 것 | 카드 아래 「미리 받아 둔 엔진 답」 + 받은 시각 |
| `DESK_ENGINE=saved`로 띄웠을 때 시민 화면의 문의 | 엔진을 부르지 않는다. 글이 미리 받은 답과 같으면(첫 장면 대본 문의) 그 답을, 아니면 「불러오지 못함」 | 「미리 받아 둔 엔진 답」, 위쪽에 「미리 받은 답으로 보이는 중」 |
| 엔진을 부르지 못함(꺼짐 · 90초 넘음 · 오류) | 카드가 「불러오지 못함」이 되고 「다시 시도」가 생긴다 | 위쪽에 「엔진에 연결되지 않음」 |
| 고친 글 · 승인 | 화면 서버에 저장된다(`runtime/state.json`, git에 넣지 않음). 승인 전 답은 시민 쪽 길(`/api/citizen/<번호>`)이 주지 않는다 | — |
| 소관 부서 · 처리 기관 | 인용한 조례 이름으로 `docs/content/C-01_답변초안카드.md`의 표에서 붙인다(PRD 1-1절 사) | 「처리 기관은 공개 답변 사례 기준」 |
| 원문 구절 · 링크 · 시행일 | 원문 구절은 엔진이 근거로 옮기고 엔진의 구절 관문이 원문과 글자를 대 본 것. 링크 · 시행일 · 조항 원문은 `engine/data/chunks_paragraph.json`에서 코드가 붙인다 | — |

## 엔진 주소 바꾸기 (설정 한 줄)

```bash
DESK_ENGINE_URL=https://<채점 서버 주소>/ask python3 demo/desk/server.py
```

- 기본은 `http://127.0.0.1:8000`(위의 `engine_trace.py`). 주소 끝의 `/ask`는 있어도 없어도 된다.
- 화면 서버는 먼저 `POST /ask/trace`(판정 낱말 · 원문 구절 · 확인 불가 사유를 함께 주는 길)를 부르고, 없으면(채점 서버처럼 `/ask`만 있으면) `POST /ask`로 바꿔 부른다. 그때는 판정 낱말이 「판정 없음」, 원문 구절 대신 조항 원문 전체가 보이고, 확인 불가는 모두 「조항을 찾지 못함」으로 보인다(엔진 기록 없이는 「6종 밖」을 가를 수 없어서).
- `engine_trace.py`는 엔진 코드를 고치지 않고 `engine.server`를 불러와 길 하나만 더한 임시 다리다. 엔진이 같은 기록을 내주게 되면(만들 것 목록 E1) 필요 없다.

## 화면 배치와 시민 신청서 (2판)

- 배치: 맨 위 띠 + 왼쪽부터 시민 휴대폰 → 작업 칸(문의 목록과 답변 초안이 번갈아) → 오른쪽 넓은 서울 지도. 맨 위 띠 오른쪽의 글자 버튼 셋(시민 화면 · 문의 목록 · 답변 초안)으로 칸을 접고 편다. 근거와 견준 안은 `docs/DESIGN.md` 1절.
- 시민 화면은 서울시 응답소 민원신청 화면의 항목 · 순서 · 낱말을 따랐다(신청인 정보 → 처리결과 수신 → 민원발생지역 · 제목 · 내용 → 민원공개여부 → 개인정보 수집 · 이용 동의 → 등록). 기관 이름 · 로고는 쓰지 않고 「시연 화면입니다 …」를 늘 보인다. 신청인 정보는 고칠 수 없는 가상 값이고, 실제 본인인증 화면은 흉내 내지 않는다.
- 초안은 「내용」만으로 만든다(제목은 담당자 화면에만 보인다). 서버는 제목 · 민원발생지역 · 공개 여부 · 수신 방법을 함께 저장하고, 동의하지 않은 신청은 받지 않는다(400).

## 화면 문구

- 원본은 `docs/content/A-01_답변화면.md` · `C-01_답변초안카드.md` · `U-02_시민문의.md` 셋이다. 화면은 글자를 이 파일에서만 읽는다(`/api/text`). 파일을 고쳐 저장하면 새로고침 없이 1~2초 안에 화면이 바뀐다. 고치다 깨진 파일이면 마지막으로 정상이던 글자로 보이고 위에 알림이 뜬다.
- 모습 규칙은 `docs/DESIGN.md`.

## 파일

| 경로 | 내용 |
|---|---|
| `server.py` | 화면용 얇은 서버(표준 라이브러리만): 문의 저장 · 엔진 부르기 · 고친 글과 승인 · 시민 쪽 답 · 재생 · 처음 상태로 |
| `engine_trace.py` | 엔진 + 화면용 기록 길(`/ask/trace`). `/ask` · `/health`는 채점 서버 그대로 |
| `data/replay.json` | 시연 문의(첫 장면 대본 1건 + 재생 11건). 번호는 `_orch-tools/reports/문의세트/`의 번호, G는 팀이 쓴 가상 문의 |
| `data/saved.json` | 미리 받은 엔진 답(새 흐름 7판, 11-11). 다시 받기: 엔진을 띄운 뒤 `python3 demo/desk/server.py --save`(없는 글만 받는다, 모두 다시 받으려면 `--all`) |
| `data/places.json` | 지도 점 자리(대략 위치). 급지 · 공원 구분 자료는 아직 없다 |
| `web/` | 화면(MapLibre GL JS 5.6.0 + OpenFreeMap, 키 없음) |
| `web/data/seoul.geojson` | 서울특별시 경계(지도에서 서울 밖을 가리고 움직일 범위를 묶는 데 씀). OpenStreetMap relation 2297418, Overpass API 2026-11-11 받음, 0.0004° 단순화 |

## 스스로 시험

```bash
python3 demo/desk/server.py --selftest
.venv/bin/python demo/desk/engine_trace.py --selftest
```

둘 다 엔진 · 인터넷 · 열쇠 없이 몇 초에 끝난다.
